Fail CI when evidence goes stale.

Verify Frozen Artifacts checks that the SHA256 values declared in a manifest or AI-agent evidence packet still match the bytes on disk. A changed artifact, a missing file, or an ambiguous current claim makes the check fail closed.

View on GitHub Use v0.2.0

Why this exists

Artifacts drift

A file is edited after freezing, but the record still claims the old bytes.

Evidence mixes states

The same document can contain current, historical, and superseded hashes.

CI should fail closed

Missing files and unparseable claims are not treated as success.

Run it in 30 seconds

git clone https://github.com/wu350891451-jpg/verify-frozen-artifacts.git
cd verify-frozen-artifacts
python3 scripts/verify_declared_hashes.py demo/manifest.sha256 --root demo

Use it as a GitHub Action

- uses: actions/checkout@v4
- uses: wu350891451-jpg/verify-frozen-artifacts@v0.2.0
  with:
    declaration: artifacts.sha256
    root: .

Built for evidence packets

The evidence checker separates current, historical, superseded, and stale declarations. A stale current value still fails. Only byte identity is verified; this is not a claim that the underlying data is true or trustworthy.
