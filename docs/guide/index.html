Verify Frozen Artifacts

Verify SHA256 claims in GitHub Actions

This guide shows how to fail a workflow when a frozen artifact or AI-agent evidence packet claims a SHA256 that no longer matches the bytes on disk.

What the action checks

The action compares declared SHA256 values with the files in a checked-out workspace. It fails closed: a mismatch, a missing file, a parse error, and an unresolvable declaration are not treated as a pass.

It is intended for post-freeze edits, stale evidence claims, and files that were silently replaced or never written. It does not establish who produced a file or whether the underlying data is correct. Use Sigstore, cosign, in-toto, or SLSA when publisher authenticity is part of the threat model.

Use the action with a SHA256 manifest

Commit a sha256sum-style manifest such as artifacts.sha256, then add this job to a workflow: 

name: Verify frozen artifacts

on: [push, pull_request]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: wu350891451-jpg/verify-frozen-artifacts@v0.2.0
        with:
          declaration: artifacts.sha256
          root: .

Pin the action to a full commit SHA in security-sensitive repositories. The v0.2.0 tag is convenient for evaluation.

Verify an AI-agent evidence packet

Evidence documents often mix the current delivery state with historical and superseded values. Point the action at the packet directory instead of a single manifest: 

- uses: wu350891451-jpg/verify-frozen-artifacts@v0.2.0
  with:
    evidence-path: sys-agents/tasks
    workspace: .

Set either declaration or evidence-path, not both. The checker classifies declarations as current, historical, superseded, stale, or unresolved. Only current declarations gate the exit code.

Exit codes

CodeMeaning
0Every current declaration matched.
1Mismatch, missing file, or ambiguous path.
2Usage or parse error.
3No document contained a current declaration.
4A current declaration had no resolvable path.

Codes 2, 3, and 4 are failures, not passes.

Run the CLI locally

git clone https://github.com/wu350891451-jpg/verify-frozen-artifacts.git
cd verify-frozen-artifacts
python3 scripts/verify_declared_hashes.py demo/manifest.sha256 --root demo

The CLI also accepts JSON objects mapping a path to a digest and JSON arrays with custom field names: 

python3 scripts/verify_declared_hashes.py claims.json --format json --root .
python3 scripts/verify_declared_hashes.py claims.json --format json --root . \
  --name-key artifact --hash-key digest

Common failure modes

  • Mismatch: the artifact changed after the digest was recorded.
  • Missing file: the manifest points outside the checked-out tree or to a file that was not committed.
  • No current declaration: the evidence packet contains only historical or superseded hashes.
  • Unresolved path: a digest appears without a path that can be tied to a file.

FAQ

Is this a signature or provenance verifier?

No. It checks byte identity only.

Does a pass prove the data is correct?

No. A pass means the bytes still match the declaration.

Can I use it outside GitHub Actions?

Yes. The repository includes dependency-free Python CLIs for local checks and other CI systems.
